## 原始接口范围

- [`m1-room-blocks.openapi.json`](m1-room-blocks.openapi.json) 定义 M2、M3 向 M1 同步整室占用或下架状态的内部 HTTP 接口。
- M2 在整教室申请获批后占用指定时段；驳回、撤销或超时撤销后释放。M3 在自习室维修中时下架全部座位，验收通过后恢复。
- M1 是座位可预约状态的写入方，须保留来源 `M1`、`M2`、`M3` 与来源 ID，以支持追溯。M2、M3 不直接写 M1 数据库。
- 身份、通知、审计提供方及 M2/M3 自有业务接口仍待各组定稿；D-02 与 M1 本次新增的契约不等于其他提供方已可用。

## 写回约定

以 `(sourceSystem, sourceId)` 作为稳定来源键：`M2` 的 `sourceId` 指整教室申请/占用 ID，`M3` 的 `sourceId` 指报修工单 ID。一个来源键在同一时刻至多对应一条整室状态。调用方对该来源键递增 `revision`，用 `PUT` 发送完整目标状态 `ACTIVE` 或 `RELEASED`。

`ACTIVE` 表示该来源对指定房间及时间区间施加阻断；`RELEASED` 表示该来源不再阻断，并保留来源键与最后版本作为墓碑，防止迟到的旧 `ACTIVE` 重新生效。M2 必须给出开始和结束时间；M3 可省略结束时间表示开放终止。所有时间使用 UTC、`Z` 后缀，区间采用 `[startsAt, endsAt)`；省略结束时间表示 `[startsAt, +∞)`。结束时间必须晚于开始时间。

同一来源键、同一 `revision`、相同完整请求重复发送，应返回同一已应用状态；较旧 `revision` 或同版本不同请求返回 `409`。调用方在超时或 `503` 后可用同一请求重试，不能为一次重试增加版本。`401`、`403`、`404`、`409`、`422` 不做盲目重试。即使 `RELEASED` 先于该键的 `ACTIVE` 到达，也应记录版本墓碑；这个约定需要在集成测试中验证。

此接口只解决来源状态同步。**M1 个人预约与 M2 整教室占用发生冲突时的裁决、审批状态切换顺序、重试上限与补偿流程仍待组内决策**；实现前须补充 ADR 与对应验收用例。

## 变更流程

1. 发起 PR 时更新共享契约和本模块需求/决策记录，列出受影响调用方、所需调整、兼容性和迁移顺序。其他业务模块由其负责组在各自授权任务中更新实现和状态，不由当前模块代理代改；D 等公共部分按明确任务范围及评审要求处理。
2. M1 与对应调用方共同评审写回字段和行为；涉及 D、数据库 schema 或公共错误格式时由受影响模块组一并评审。评审人员和公共层归属由项目组正式确定。
3. 先更新契约，再由各模块按分工实现接口与消费者，并加入契约验证和跨模块集成测试。提供方功能尚未实现时，调用方记录缺口和未验证范围，不把提案当作可用接口。当前空壳阶段只验证契约文件可解析，不以虚假的业务测试代替行为验证。
4. 破坏性修改使用新路径版本或有明确迁移窗口，不能静默改变旧接口语义。
