# D 身份、通知、审计消费方契约提案 v0.1.0

状态：**proposed，提供方未实现，未完成真实联调**。本任务用户只授权 M1 和 D-02，本文记录消费需求，不替代 D-01/D-03/D-04 所属组的设计及批准。D-02 权威契约另见 `d-master-data.openapi.json`。

## 身份 D-01

- `POST /api/v1/auth/login` 输入 `{username,password}`；预期返回 `{accessToken,expiresAt,user}`。
- `GET /api/v1/auth/me` 以 `Authorization: Bearer <session>` 验证会话；预期返回 `{id,displayName,departmentId,permissions}`，departmentId 可为 null。
- `POST /api/v1/auth/logout` 撤销会话。前端存储清理不能代替服务端撤销。
- 权限最小集：`seat:reserve` 学生预约，`room:manage` 主数据与房间屏幕，`operations:read` 运营事实查询。系统配置权限由 M1 契约明确，提供方需映射受控角色；消费方不能让用户自行声明院系/权限。
- 缺失/失效凭据 401；已认证但权限不足 403；提供方故障 503；禁止故障自动回退开发身份。
- 会话有效期、角色管理、账号初始化和真实身份纠错尚待 D-01 提供组确认。HTTP 明文只用于本机合成演示，真实身份部署需要 HTTPS。

## 通知 D-03 与审计 D-04

M1 将业务触发与投递分开：本地事务保存发件箱，独立重试调用提供方。接口拟为服务 Bearer 认证的 `POST /internal/v1/notifications` 与 `POST /internal/v1/audit`，服务凭据通过环境配置，不进入浏览器。精确消费请求、幂等键和接收响应以 M1 公共契约的依赖章节为准；D 提供组必须评审后对齐。

通知至少传稳定幂等键、接收用户 ID、事件类型、预约引用与必要显示信息；审计至少传稳定事件 ID、动作、操作者 ID、对象引用、发生时间、结果。不得记录密码、会话令牌、签到码或真实学生姓名。接收不等于送达；实际渠道、投递/阅读语义、查询、重试与数据保留由 D 提供组确认。站内通知是用户接受的首版方向，本次不实现 D 通知中心。

## 临时依赖与兼容性

显式开发模式下可用固定合成身份和模拟接收记录练习消费方业务。它们不是 D 实现、真实通知或真实审计证据。精确路径/配置/替换触发见 M1 与 D-02 任务记录。正常模式只接真实 HTTP，不提供假成功。后续提供方接口如有差异，应先修订契约、调整消费者并进行真实联调，再移除临时文件及入口。
