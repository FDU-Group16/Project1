# AI 开发任务模板

每次委派实现任务前复制此模板，填写具体内容并关联需求 ID。当前框架阶段的业务任务尚未启动。

## 协作需求与 develop 同步（按需）

先判断本任务是否实际依赖其他业务模块或 D 等公共部分。单模块独立任务记录“不触发”，不强制 fetch；同一业务模块的前后端衔接不自动视为跨模块协作。需要协作时再按根目录 `AGENTS.md` 尝试同步，记录以下证据。

- 是否触发同步、具体依赖哪个模块的什么能力：
- 本模块允许修改的目录；所需 D 等公共修改的范围与验收条件：
- 工作分支与工作区路径：
- 采用的团队远程（通常为已配置的 `origin`）：
- 本地修改、未跟踪文件及未完成 Git 操作的检查结果：
- 获取远程 develop 的时间、结果及提交 SHA：
- 同步结果（不触发 / 已包含 / 安全快进 / 已获取但待人工集成 / 获取失败）：
- 实际 HEAD；若只读取远程引用，注明引用与 SHA：
- 已重读的全局/局部规则、模块状态和依赖契约：
- 所需能力的实现情况、证据版本与可联调范围；缺失或未确认时说明影响及下一步：

只有当前工作分支可安全快进时，代理才按规则执行 `git merge --ff-only <remote>/develop`。分叉、冲突或工作区不满足安全条件时交由人处理；不自动 stash、提交、reset、rebase 或覆盖。不得借此更新 `main`/发布分支、合入 `develop` 或推送。

其他业务模块功能缺失时，阐明缺口并记录在本模块任务/状态，不修改对方代码、测试、规则或状态文件；可按下方“并行开发与临时依赖”在本组范围内建立最小开发/测试替身。D 等公共部分可按当前任务明确的需求、范围和验收条件修改，遵守契约优先及受影响方评审。fetch 失败只能说明当前检出状态与远程未确认，不能断言远程没有实现。

## 并行开发与临时依赖（按需）

执行根目录 [AGENTS.md 的临时依赖规则](../AGENTS.md#parallel-development-and-temporary-dependencies)。不需要替身时填写“不使用”；需要时按每项依赖分别填写，并从本组 `STATUS.md` 链接到本清单。替身放在本组授权目录内，通过独立接口或适配器替换，只实现本组验收所需的最小行为。

- 稳定依赖 ID、消费模块、提供模块与缺失/未确认能力：
- 契约路径、版本和审批状态；临时假设及待协调差异：
- 需要模拟的成功与失败场景，以及本次未覆盖的行为：
- 标记为 `TEMPORARY-DEPENDENCY` 的文件或专用目录 README 路径：
- 可替换/删除的精确文件、假数据、配置项及启动入口清单：
- 必须保留的本组业务逻辑、真实 API 客户端、错误处理及长期行为测试：
- 显式启用/关闭方式、开发或演示中的模式标识；如何确认正常运行和部署使用真实依赖：
- 替身维护组、提供方责任组、接入和清理责任组；当前任务授权目录：
- 替换触发条件、后续集成任务需授权的路径及真实联调验收条件：
- 当前证据：本组已实现范围 / 替身验证范围 / 真实联调未验证范围：

临时假设不得替代团队业务决策；公共接口提案仍放在 `contracts/`。真实依赖失败时不得自动回退为模拟成功。替身测试只验证本组行为，不能作为提供方已实现、跨组状态写回成功或部署可用的证据。

真实接口可用后，由明确授权的集成任务核对契约、切换真实适配器并完成联调，再按清单清理临时部分、重新运行受影响检查及 `bash scripts/check.sh`，并更新本组交接记录。“可修改/丢弃”标记不授权自动处理合并冲突、丢弃已有改动或删除本组正式业务代码。
