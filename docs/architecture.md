# 系统基本架构（提案）

状态：**proposed / 待组内评审**。本文定义框架目标与接口边界，不表示业务模块已实现。依据课程任务书，项目组最终交付一套开发、测试、生产环境，三个业务模块和公共层共同部署；评审时需要展示跨模块网络调用、可追溯状态写回、迁移、自动测试、发布与回退。

## 服务边界

| 应用 | 拟负责的数据与能力 | 当前阶段 |
| --- | --- | --- |
| `m1-api`（`services/m1`） | 自习座位预约与可预约状态；接收 M2/M3 整室状态写回，保留来源追溯 | 只搭应用空壳和接口契约 |
| `m2-api`（`services/m2`） | 整教室申请与审批；通过公开接口向 M1 同步时段占用 | 只预留独立服务边界 |
| `m3-api`（`services/m3`） | 报修工单；通过公开接口向 M1 同步维修下架与恢复 | 只预留独立服务边界 |
| `d-api`（`services/d`） | 候选公共层：身份/RBAC、空间与座位主数据、通知、审计 | 边界和模块组归属待决 |
| `web` | 学生和管理端的 Web 入口 | 只搭前端工程空壳 |

四个 API 是有独立 FastAPI ASGI 入口的进程和部署单元（`services.m1.main:app`、`services.m2.main:app`、`services.m3.main:app`、`services.d.main:app`），由 Uvicorn 启动，不共享业务数据库表或内部服务类。前端是 Vue 3 + Vite 应用，通过 HTTP 公共接口访问服务；服务间只经版本化 HTTP 接口通信。单仓库共享工程配置、文档和契约；后端依赖由根目录 uv 项目管理，前端依赖由 `apps/web` 中的 npm 项目独立管理。共享代码只放技术性基础设施，不能把跨模块业务实现放进公共包。附加自然语言业务代理若以后实施，也只能调用公开接口。

## 关键集成链路

```text
M2 审批状态 ── PUT 来源版本 ──┐
                              ├──> M1 整室阻断记录 ──> 座位可预约状态/来源追溯
M3 维修状态 ── PUT 来源版本 ──┘
```

共享契约见 [`../contracts/m1-room-blocks.openapi.json`](../contracts/m1-room-blocks.openapi.json) 与 [`../contracts/README.md`](../contracts/README.md)。写回请求用 `M2`/`M3` 加稳定 `sourceId` 标识来源，递增 `revision`，以 `ACTIVE`/`RELEASED` 表达目标状态。M1 应在来源记录中保存来源类型、来源 ID、版本、时间区间和状态；自身预约引起的座位状态也须标识 `M1` 来源。房间与座位的主数据权威来源拟由 D 承担，但主数据变更如何推送到 M1 尚待定义。

所有业务时段用 UTC 传输和存储，按 `[开始, 结束)` 解释，显示时由客户端转为本地时间。M2 区间有明确结束；M3 可以开放终止。不同来源的阻断可能重叠；释放一个来源不得消除其他仍生效的阻断。M1 个人预约与 M2 整室占用冲突时的裁决，及跨服务业务状态切换顺序，须在实现前通过 ADR 决定。

## 数据、环境与交付骨架

- PostgreSQL 可在每个环境使用一套实例；目标是每个服务拥有独立 schema/账号，服务不得跨 schema 读写。当前 Compose 尚未配置业务 schema、账号或表。生产数据与种子数据分离。
- 每个服务的结构演进通过版本化迁移脚本管理；从空库回放、迁移重复执行与幂等种子数据须在后续迭代验证。迁移工具尚未选定，不在本轮创建虚假的业务表。
- Docker Compose 作为单组环境的部署编排候选；开发、测试和生产使用同一组应用镜像及可审查的环境差异。数据库就绪要由健康检查判断。当前运行环境的容器守护进程状态不代表未来部署环境。
- GitHub Actions 在 PR 和提交时执行 `uv sync --frozen`、`npm --prefix apps/web ci`、契约和服务冒烟检查、Web 构建；以后补充实际业务行为测试，失败时停止后续部署。统一检查入口为 `bash scripts/check.sh`，具体检查项以脚本为准。`develop` 检查通过后的测试环境部署配置已编写，仍待服务器凭据和首次远端运行验证；生产经人工批准并记录版本 tag 与回退目标。保护规则和审批机制需根据仓库套餐与权限实测后确定。
- 组内约定部署窗口或等效串行机制，避免一个模块部署时其他模块集成测试误报。跨模块、公共层与 schema 变更需受影响成员评审；代码冲突由人处理。

## 本轮完成边界与后续顺序

本轮只交付可审查的工程目录、基础启动/健康检查、配置样例、共享契约、项目级 AI 规则和流水线框架。**不创建预约、审批、工单、RBAC、通知、审计等业务端点或业务表。**

后续按顺序推进：团队确认 D 归属与边界 → 形成带验收标准的需求基线 → 评审跨模块契约和冲突政策 → 各模块独立实现及行为测试 → 联调写回链路 → 迁移和测试环境自动部署 → 生产审批、版本标记和回退演示。未完成需求保持可追踪记录，不从清单中删除。
