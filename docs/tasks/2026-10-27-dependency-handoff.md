# 临时依赖发现与集成交接

## 目标与范围

- 用户希望提供方完成后能发现消费者仍未接入真实接口，避免仅在本模块注释中隐藏缺口。关联 E-07/E-09，跟踪 M1-01/M1-05、D-02 和公共 Web 身份依赖。
- 方案：各提供方/消费方维护结构化记录，工程脚本自动汇总、反查源码标记；提供方状态与消费方验收分开。稳定模块索引只链接流程，不维护共享进度表。
- 允许修改：`scripts/check-dependencies.py`、`scripts/test-dependencies.py`、`scripts/check.sh`；`docs/temporary-dependency-handoff.md`、本任务、任务模板/模块索引、需求 E-07 证据链接及 README/AGENTS 工程规则；M1、D-02、公共 auth 的 `DEPENDENCIES.json` 与 D 的 `PROVIDES.json`；上述消费者的 STATUS 和临时清单链接。
- 不实现 D-01/03/04 或 M2/M3 业务，不改接口字段、schema、运行配置，不代改 M2/M3 私有状态，不自动删替身、发消息或生成新任务。无新临时实现。
- 工程集成由本任务负责；提供方记录由 M2(D-01)/M3(D-03/D-04) 维护，消费者记录由 M1、D-02 与 Web 公共维护方分别维护。正式评审人员与记录未知，不以工具校验代替人工接口评审。

## 验收与关键取舍

- 提供方可按能力或负责组查询受影响消费者、其集成状态、临时源码位置和下一步。
- `integration_ready` 不自动把消费者标成完成；源代码有开发替身不表示生产正在使用替身。
- 默认 CI 对未登记标记、未知提供方、重复 ID、无效路径/字段、缺少验收证据、已清理却仍残留 TEMP 标记等不一致失败；单纯等待提供方或未完成接入仅提示，保证并行开发。
- 指定能力/消费方的 `--require-complete` 用于集成验收，拒绝未完成或空选择；不能靠筛选隐藏全仓记录错误。
- 验证绑定提供方与消费方代码 revision、环境、命令和本地证据文件；提供方变更时提示复核，不擅自覆盖历史验收。工具校验的是登记一致性，不能证明外部服务真实可用。
- 行为测试通过真实 CLI + 临时目录覆盖 ready 未接入、严格检查、成功清理、残留替身、缺证据、多提供方/共享标记、未知 ID/路径、筛选及排除规则，根检查通过。
