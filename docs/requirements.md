# 需求与验收基线（草案 v0.1）

> 来源：[课程任务书](../任务书.pdf)，页码以下均指 PDF 页码。本文件将任务书中的要求编号，供接口契约、任务、提交和测试引用。2026-10-22 建立；最初为全业务未实现；2026-10-22 的 M1 / D-02 实施与剩余集成范围见下表。

## 范围与状态

- `已明确`：任务书直接给出业务规则或工程约束；仍需在实现前补全边界情形。
- `待细化`：任务书只给方向，尚不构成可直接开发的完整需求。表中的验收方式是讨论起点，具体角色、阈值、流程、异常处理须经组内确认。
- 每个需求后续都应关联实现 PR/提交、公开接口或页面、自动化测试和部署版本。未完成项保留在本文件，不能从清单中删除。
- 本次用户授权实施 M1-01～08 与 D-02。D-01/03/04、M2/M3 提供方及团队/部署验收保留未完成状态；不能将消费方替身验证当作真实提供方验收。

## 尚需组内确认的关键问题

1. M2 的申请资格、审批层级、超时时长、已存在 M1 预约时的处理方式。
2. M3 的派单、维修/升级/验收规则，以及同一自习室多张维修工单并存时的恢复条件。

4. 统一时间与时区、预约开放窗口、冲突/取消规则、API 幂等和跨服务失败补偿。
5. 公共层 D 的子域任务分工已确认：M1 负责 D-02，M2 负责 D-01，M3 负责 D-03/D-04；具体评审、首期协调及轮值细节按 [ADR 0002](decisions/0002-d-ownership.md) 单独完善。
