# M3 独立行为验证记录

日期：2026-10-27。验证对象为本工作区 `codex/m3-rebuild`，不是远端发布或真实提供方验收。

## 方法与覆盖

`../tests/test_independent.py` 使用真实 SQLAlchemy/Alembic、工单业务服务、worker 和 HTTP 客户端；替身仅在 D 目录边界与本机真实 HTTP 服务边界。未替换被测 M3 逻辑。时钟通过既有依赖入口注入，精确检查截止时间及租约边界。

- 历次实际维修者重派后仍不得验收，即使后来取得管理员角色；对象不可见、越权、旧版本冲突、重派撤销旧维修者访问，以及重派不延长 SLA。
- 并发创建的幂等键去重；截止前一微秒不升级、到期升级；并发 SLA 扫描只追加一次历史；返工产生新的 SLA 阶段，待验收时停止计时。
- 两张同房间工单采用独立来源；验收只发送当前来源的高版本释放；收到有效回执之前不推进维修或关闭状态。
- 13 类异常 HTTP 回执不得推进状态，包括错误来源、房间、版本、布尔版本、状态、非法 UTC 日期、未知字段、缺字段及重复 JSON 键。
- 真实 HTTP 503 退避与五次预算、管理员显式重试仍保持完整请求和关联 ID；HTTP 超时保留待同步状态。
- 多 worker 并发只产生一个有效租约；过期租约不能覆盖新租约；连续崩溃也消耗五次预算；数据库重启后保留 outbox 并恢复处理。
- 空库及重复 Alembic 迁移、持久化、PostgreSQL `m3` schema 隔离；生产配置拒绝开发目录、开发 HTTP 模式及 SQLite。

## 实际证据

- 独立检查第一次在受限沙箱执行：3 个无网络用例通过，HTTP 用例因操作系统禁止绑定回环端口而中止。该错误为环境限制，不作为业务失败或成功证据。
- 主任务在具备回环端口权限的环境执行最终全量测试，报告 SQLite **63 passed**，本机真实 PostgreSQL **16.2：63 passed**。这些结果覆盖独立检查与后端 API 检查；PostgreSQL 18 的远程 CI 尚未运行。
- 主任务报告 `bash scripts/check.sh`、Vue 类型检查及生产构建通过，真实浏览器完整流程与 7 组共享页面回归通过。浏览器详细证据由主任务维护。
- 定向变异入口：`.venv/bin/python services/m3/tests/mutation_check.py`。主任务实际执行：**正常目标 3 passed；三个变异全部 KILLED**，源码摘要前后一致。脚本先在隔离副本验证三个正常目标，再分别破坏对象权限、提前进入维修状态、绕过回执校验，要求对应目标出现断言失败；失败原因不是断言或正常基线不通过时整体退出失败。脚本清除数据库环境覆盖并使用临时 SQLite，不触碰工作区代码或现有数据库。首次执行已发现权限变异但脚本误判 pytest 的 `E assert` 输出；补齐短格式断言识别后最终三项通过，未放宽业务断言。
- `test_process_restart.py` 补充真实子进程在 durable claim 后异常退出、租约到期由新进程通过 HTTP 恢复，以及 502/504 暂时错误和 400/401/403/404/409/422/500/302 永久错误；已包含在上述两次 63 项完整执行中。

## 安全执行与剩余边界

`M3_TEST_DATABASE_URL` 只能指向一次性测试数据库；独立 fixture 清空该数据库内 M3 业务数据，必须显式设置 `M3_TEST_ALLOW_RESET=1`。设置 `M3_REQUIRE_POSTGRES=1` 时，缺少真实 PostgreSQL URL 会失败，不能用 SQLite 或跳过替代。不同测试进程不得同时共享同一数据库。

本机 HTTP 替身证明 M3 的请求、回执处理及本地状态行为，不能证明真实 M1 的座位下架、M2/个人预约来源保留或 D 的身份与资源授权。相关跨组契约仍为提案，必须由提供方上线后联合验证。未宣称已合入 develop、部署或通过人工评审。
