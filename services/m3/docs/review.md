# M3 评审与交付说明

在 M1 基线 `99ce858` 上实现 M3 报修工单。用户能创建报修，管理员派单，维修人员开工和完工，报修人或附理由的管理员验收；拒绝验收回到维修中。开始维修和验收通过分别写入耐久 outbox，由后台通过 HTTP 请求 M1；只有有效回执才能进入维修中或关闭。实现包含取消、重派撤权、防自验、一次评价、可配置 SLA、幂等和版本冲突。

## 建议审阅顺序

1. [契约](../../../contracts/m3-work-orders.md)、OpenAPI、局部 AGENTS 与 [实施记录](implementation.md)：确认权限、状态、24h/48h 与外部依赖边界。
2. `services/m3/`：SQLAlchemy/Alembic 存储、状态机、目录适配、M1 HTTP 校验及 worker；生产缺少 D 时关闭业务，开发替身独立且显式启用。
3. `apps/web/src/modules/m3/`：工作台、报修与详情，演示模式提示、角色操作、错误/重试、身份切换隔离；公共部分只增加 HTTP 技术层和 M3 代理。
4. CI/Compose/启动脚本及 `tests/`：数据库迁移先于 API 启动，PostgreSQL 18 测试失败阻止交付，真实网络、子进程恢复和浏览器行为验证。

验证结果见实施记录：本地 SQLite/PostgreSQL 16.2 各 63 项通过，根检查、构建、原有部署测试与浏览器回归通过。PostgreSQL 18 由 CI 执行但未产生远端结果。M1/D 真实业务、Docker 镜像构建及上线迁移尚未验收。
