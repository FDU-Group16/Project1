## 任务边界

M1 维护本模块页面、组件、筛选与预约状态、API 适配及后端资源授权。统一登录与 HTTP 认证接入按 [D 分工与公共前端治理记录](../../../../../../docs/decisions/0002-d-ownership.md) 由 M2 拟议维护。房间/座位主数据属于 D 子域，M1 业务服务维护预约和有效可约状态。

首期目标是“座位搜索、我的预约查询、公共登录接入”。预约提交、取消、签到、提醒、违约、运营统计和 D 管理页面按独立任务推进。相关业务契约未定稿，不能以原型数据替代真实联调。

## 座位搜索

按“选时段 → 看房间 → 看座位”组织。

- 上方显示日期、开始/结束时间、“仅看带插座座位”和查询按钮。
- 按北京时间展示，API 使用 UTC；整点小时、时长上限、开放窗口依据后端规则与配置。
- 房间结果显示名称、开放时间、目标时段的可约情况与插座信息。
- 座位按编号列表或规则网格呈现；没有真实空间布局契约时，不把规则网格当成实际平面图。
- 时段改变后清除座位选择，结果标记待重新查询；查询失败保留输入，空结果提供调整时段或清除筛选的动作。
- 房间范围由后端依据身份过滤。楼栋、楼层、地图等尚未确认的字段不作为首期必需条件。
- 后续提交预约必须重新校验可用性；发生冲突时保留查询条件并引导重新选座。

## 我的预约

以“当前预约 / 历史预约”切换查询范围。记录突出房间、座位、日期时段及状态；提供首次无预约、加载、失败重试和历史分页设计。状态名称及可操作项由 M1 契约决定。

后续详情、取消、签到仅在规则允许时展示或启用；未完成请求防止重复提交，超时不直接视作失败后盲目重试。历史再次预约仍检查当前权限、开放时间与冲突。

## 身份接入与权限

D 最少需提供可信稳定用户身份、院系信息、必要角色/权限及后端身份验证方式。会话载体、有效期、退出/续期与错误语义由共享契约确定。

M1 通过公共入口使用身份状态；进入受保护页面前恢复会话，登录成功返回有效站内目标页。退出、过期、身份切换时清除前一用户的数据。前端展示不能代替以下后端检查：

- 学生只能查询/预约向其开放的房间，院系限制不能通过直接调用 API 绕过。
- “我的预约”按服务端确认的身份查询，篡改用户 ID 或预约 ID 不能访问他人数据。
- 每项业务操作同时验证身份、资源范围、归属及预约状态。

## 组件与验收

页面、房间/座位组件、预约卡片、业务状态和筛选放在 modules/m1/；公共控件、登录状态和请求基础设施使用 shared/。在首个已评审接口任务中创建 api.ts，不在组件硬编码服务地址或凭据。

首期实施验收需覆盖：正常/加载/空/错误/无权限、手机窄屏、键盘、直达与刷新、查询条件保留、登录返回、过期清理、身份切换、跨院系与跨用户 API 越权拒绝。现有原型仅验证本地交互，尚无真实登录或业务接口证据。

验证与后续集成缺口持续记录在 [M1 前端状态](../STATUS.md)；统一检查通过不能代替业务验收。
