| 详情与处理 | `pages/OrderDetailPage.vue` | 派单/重派、开修、完工、验收、返工、取消、评分；按钮按当前身份和状态展示，后端仍是授权权威 |

| 操作追溯 | 详情时间线 | 展示服务端历史、操作者、状态与时间，UTC 转北京时间；没有捏造通知送达 |

## 2026-10-27 上传前复查修复

复查发现：维修员 A 已打开一张已派单工单，调度在其他会话将其改派给 B 后，A 刷新收到 404，旧详情和开修按钮仍留在页面。服务端会拒绝动作，但页面没有及时清除失效信息。已在 `OrderDetailPage.vue` 的读取及动作错误路径处理 401/403/404：清除工单、维修/取消/返工/评价等草稿、旧成功提示，并停止动作；错误提示保留在详情之外。网络/服务错误则保留明确标注为旧快照的数据，要求成功刷新后再操作。

`tests/adapter.test.cjs` 新增 4 组回归测试，直接执行 SFC 的实际 script setup 与 Vue 响应式状态，仅替换路由、生命周期和网络边界。分别验证读取权限丢失（401/403/404）、动作权限丢失（401/403/404）、网络故障与恢复，以及旧 GET 在撤权后迟到不能恢复工单。10 项测试全部通过；最终统一类型/构建与浏览器结果由主任务记录。
