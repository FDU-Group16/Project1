# M3 报修前端

本副本在 `develop@13dcd59f9a46c859f8593b530d7aa54c27faaf1f` 上接入 M3 工单实现，保留 develop 的公共登录、请求层、M1/D-02 和其他模块。原来的独立 M3 工作目录不修改。字段及动作以 [M3 契约](../../../../../contracts/m3-work-orders.md) 为准，后端集成范围见 [实施记录](../../../../../services/m3/docs/implementation.md)。

## 页面与请求

- `/m3`：可见工单概览、标题/编号/房间搜索、状态/房间筛选；我的报修、分配给我、待我验收和超时待办。服务端先执行对象权限过滤，前端在已授权结果中筛选；每 15 秒刷新。
- `/m3/new`：房间目录、分类、标题和描述表单；同载荷失败重试保留幂等键，防止重复创建。按钮和字段在请求中禁用。
- `/m3/work-orders/:id`：真实工单、阶段、历史、派单/重派、开工、完工、验收/返工、取消、评价和同步重试。操作使用后端 `allowedActions`，携带选中动作时的 `version`；冲突或不确定响应后刷新详情，用户重新选择动作确认。
- 等待下架/恢复时每 3 秒读取后端，其余详情每 5 秒更新。浏览器标签隐藏时暂停请求，离开页面取消请求。回执前保留 `BLOCK_PENDING`/`RELEASE_PENDING`，浏览器不访问 M1。
- `api.ts` 使用公共 `shared/api/client.ts`，以 `request('m3', '/v1/...')` 得到 `/api/m3/v1/...`；共享层提供 Bearer、超时、错误处理和身份变更检测，模块仅封装工单业务。不开启新的状态/UI 库，新增样式为组件局部样式。

## 公共身份接入与依赖清单

所有 M3 路由设置 `requiresAuth`。访客先进入公共 `/login`，不在访客页发出 M3 业务请求。M3 不读取或保存登录令牌，不消费 `/context.demoIdentities`，不构造本模块身份选择、密码表单或另一个登录状态。`M3Shell.vue` 使用共享登录状态，调用后端 `/me` 获取报修角色；操作授权仍由后端执行，前端不根据公共权限自行赋予维修角色。

共享 `auth.epoch` 改变时立即取消会话和页面请求、清空 M3 上下文，根 App 的既有规则重新挂载当前路由；401、退出和过期统一走共享身份清理及登录重定向。模块内 `session.ts` 只传递已确认的 M3 业务身份和 API，既不存储凭据，也不提供登录。

[DEPENDENCIES.json](DEPENDENCIES.json) 登记 **WEB-M3-D01**（D-01，integrating）。真实 D-01 提供方仍待集成，因此无真实身份验证记录；公共开发身份的临时代码由 [shared/auth 的依赖清单](../../shared/auth/DEPENDENCIES.json) 及 [替换说明](../../shared/auth/docs/auth-integration.md) 维护。本模块没有自己的开发身份替身文件或待删除标记；`api.ts` 的契约假设标记关联本模块记录。

独立本地演示也从公共 `/login` 进入，仅在开发服务器显式设置 `VITE_USE_DEV_IDENTITY=true` 时选择合成身份，后端同时明确选择开发依赖。M3 顶部只显示依赖模式：合成身份、合成/主数据房间、M1 HTTP 替身/实际回执分别说明；真实服务故障不回退模拟成功。生产构建不显示开发身份入口。公共开发身份不会因为用于维修就自动获得主数据写权限。

替换验收由 D-01、公共 Web 和 M3 联合完成：核对真实共享会话字段及后端角色、认证失败/过期、退出与快切隔离；登记真实提供方与消费者版本后由各自所有者清理公共开发身份和后端替身。本模块保留工单 UI、共享 API 消费、取消请求、版本与错误处理。D-02 与 M1 的实际集成证据由后端任务另行登记，不能以这个前端依赖记录推断全部联调已通过。

## 验证清单

工程检查：仓库根执行 `npm --prefix apps/web run typecheck`、`npm --prefix apps/web run build`、`python3 scripts/check-dependencies.py` 和 `bash scripts/check.sh`。运行结果记入 [STATUS](STATUS.md)，构建不等于流程验收。

浏览器验收：

1. 未登录直达 M3 跳转公共登录；登录后返回原工单路径。显式开发身份与真实身份入口边界清晰。
2. 新报修→管理员派单→维修人员开工→下架确认→完工→返工或验收→恢复确认→完成→一次评价。后端返回的房间与角色贯通。
3. 重派后旧维修人员失去权限；返工/取消理由必填；管理员代他人验收说明必填；维修参与者不能自验。
4. 同步失败、重试、无权限直达、404、版本冲突、加载/空数据/网络错误；不提前宣布房间恢复。
5. 通过公共登录快速切换身份、退出或失效后，旧表单/工单和慢请求均被清理；M3 无独立身份下拉或令牌存储。
6. 320px/375px/桌面无横向溢出，表单标签和键盘焦点可访问；原公共访客及 M1/D-02 回归保持原断言。

自动化点击导航后先等待目标页标题，再定位该页表单。工作台房间筛选和新报修房间字段名称相同，不能把路由完成前对旧筛选的操作误认为新表单选择。
