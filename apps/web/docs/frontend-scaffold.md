# 前端模块骨架任务

## 目标与范围

- 关联需求：E-01、E-03、E-07 的工程基础；本任务不实现 M1/M2/M3 的业务需求。
- 目标：将静态 Vue 外壳整理为模块目录、独立路由、公共布局和公共展示组件，让各组能够在自己的目录内开始开发。
- 允许修改：`apps/web/`，包括前端依赖清单和 npm 锁文件。
- 范围外：业务 API、登录与权限、状态管理库、数据库、后端和部署配置。

## 约束与依赖

- 遵守根目录和前端 `AGENTS.md`；业务需求及契约仍保持原有未实现状态。
- 公共布局、根路由及新增依赖属于共享改动，评审覆盖 M1/M2/M3 前端使用方；具体人工评审人和 PR 在提交时补充。
- 不使用真实身份或学生数据，不将页面说明当作业务能力。

## 方案与选择依据

- 采用 Vue Router 4，将 `/m1`、`/m2`、`/m3` 接入各模块独立的 `routes.ts`，根路由汇总。使用显式路由即可满足当前规模，不引入文件路由、状态管理或 UI 组件库。
- 公共布局通过插槽和导航参数承载模块页面，不导入模块内部实现；现有首页文案迁入首页组件，模块入口只显示功能待开发的说明。
- 各模块预留 `pages/`、`components/`。`api.ts` 随首个已评审业务接口建立；公共 `api/` 和 `auth/` 目录先记录职责，不创建假请求或空登录实现。
- 备选是仅建立空目录，但不能验证模块路由和公共布局的实际连接，因此本任务同时接入可访问的静态模块页。
- 使用方式参考 [Vue Router 官方指南](https://router.vuejs.org/guide/)。

## 验收与证据

- `/` 保留工程骨架首页；`/m1`、`/m2`、`/m3` 分别显示对应模块说明，均标明业务尚未实现。
- 导航可切换模块；直接访问及刷新模块 URL 能显示正确页面；浏览器前进、后退可用。
- 模块独立维护路由和页面，公共组件只接收展示参数；根全局样式仅保留基础设置，布局和组件样式使用 `scoped`。
- 执行根目录 `bash scripts/check.sh`；浏览器检查上述路由、导航、窄屏、键盘焦点和运行错误。
- 本任务为低影响的目录重构，不新增重复实现的自动化测试。检查必须针对浏览器中实际渲染的模块标题与路由，移除对应路由时检查应失败。
- 人工审查人和提交/PR 链接由提交时记录。
