## 目标与范围

采用“统一公共外壳、模块独立页面、统一登录与反馈”，以 M1 的座位搜索和个人预约作为首批使用场景，同时保留 M2/M3 导航入口。设计阶段应用只有静态模块说明页；设计原型没有接入真实身份、业务 API 或数据库。后续 Vue 页面与可用入口以实施记录和各模块状态为准。

初始设计提交保存了设计、原型和交接记录。下述页面与交互是分阶段实施目标，不能把原型演示计为业务功能完成；Vue 落地提交单独记录实际实现和未完成内容。

## 信息架构与布局

桌面端采用顶部模块导航、左侧模块菜单和中间内容区：

- 顶部：平台名称、座位预约、整室申请、报修服务、用户菜单。
- 左侧：只显示当前模块的功能；M1 首期为“座位搜索”“我的预约”。
- 内容区：面包屑、页面标题、简短说明、筛选或主操作、业务内容。
- 用户菜单：身份信息、退出登录；管理入口依据实际权限显示，不提供自行提升角色的入口。
- 首页只承担模块入口与引导；首期不建设依赖多个服务的综合数据看板。

手机端保留三个业务入口，模块菜单可展开/收起，内容改为单列。筛选条件以可折叠区域或自然换行容纳，不能裁切表单、动作或错误信息。结果卡片按内容自动增高。

| 页面 | 建议路径 | 内容与阶段 |
| --- | --- | --- |
| 公共首页 | / | 平台说明、模块入口、登录引导；首期 |
| 统一登录 | /login | 认证入口、错误提示、登录后返回原页面；首期 |
| M1 座位搜索 | /m1 | 时间与插座筛选、房间/座位查看；首期 |
| M1 我的预约 | /m1/reservations | 当前与历史预约查询；首期 |
| M1 预约详情 | /m1/reservations/:id | 预约信息及状态允许的操作；随预约业务接入 |
| M1 签到 | /m1/reservations/:id/check-in | 编码输入与校验；后续 |
| 无权限、页面不存在 | /403、兜底页面 | 原因说明与返回可访问页面；首期公共能力 |

上表记录设计路径，当前可访问路径见实施记录；签到等后续目标并未因此自动实现。M2/M3 具体页面由相应模块组设计。D 管理页面的目录、路由和权限在各子域任务中明确，不混入公共展示组件。

## 身份、权限与公共反馈

| 状态 | 界面行为 |
| --- | --- |
| 身份恢复中 | 显示加载占位，身份确认前不展示用户数据 |
| 未登录 | 进入统一登录，保存有效的站内目标路径；不先展示未经院系过滤的真实结果 |
| 登录成功 | 返回原页面，加载该身份可访问的数据 |
| 会话过期 | 集中提示一次，清理用户数据，再进入登录流程 |
| 已登录但无权限 | 显示原因及返回入口，保留正常登录状态 |
| 服务暂不可用 | 显示失败与重试，保留输入；不把网络失败误判为退出登录 |
| 无数据 | 展示空状态与下一步操作；未取得数据不能显示为真实的“0” |
| 提交中或结果未知 | 防止重复提交；超时后按契约核对结果，再允许重试 |

登录方式由 D 身份契约决定，公共入口可承载账号表单或学校统一认证。D 提供可信身份与公共权限信息，公共前端维护会话展示；业务后端继续校验资源范围和数据归属。退出及身份切换清理前一用户的预约、筛选结果和相关缓存。并发请求失效不应重复弹出多个登录框。

## 视觉规范与可访问性

| 项目 | 建议规范 |
| --- | --- |
| 主色 | 沿用蓝绿色 #166B76，用于主要按钮、选中导航和重点操作 |
| 背景与面板 | 浅灰蓝背景、白色内容面板、细边框和少量阴影 |
| 文字 | 主文字 #172B3A；正文 14–16px，页面标题约 26px |
| 间距 | 统一采用 4、8、12、16、24、32px |
| 圆角 | 表单与按钮约 6–8px，内容面板约 10px |
| 内容宽度 | 桌面正文最大约 1200px，表单与详情保持适合阅读的宽度 |
| 手机端 | 输入文字至少 16px，主要点击区域约 44px，单列内容 |
| 状态表达 | 颜色配合文字/图标，明确说明“维修中”“不可预约”等状态 |

支持 320px 窄屏、清晰的键盘焦点与原生表单交互；错误紧邻并关联对应字段。正式弹窗需处理焦点进入、退出和返回触发控件。重要操作无需悬停即可发现。原型提供随系统变化的明暗主题作为视觉参考；正式主题范围待实施任务确认。

## 组件与状态边界

| 位置 | 责任 |
| --- | --- |
| src/shared/layouts/ | 公共外壳、导航、模块菜单和内容区布局 |
| src/shared/components/ | 按钮、输入、选择、对话框、加载、空状态、错误提示、分页 |
| src/shared/auth/ | 身份恢复、登录状态、退出清理及公共权限展示 |
| src/shared/api/ | 请求配置、统一错误和认证接入 |
| src/modules/&lt;module&gt;/ | 模块页面、API 适配、业务状态与私有组件 |

共享组件只接受展示参数，不导入业务模块内部实现。座位卡片、预约筛选和预约状态解释属于 M1；例如标签组件提供样式，M1 决定何时显示“待签到”和允许哪些操作。

沿用现有 Vue、TypeScript、Vue Router。首期先使用已有依赖，组件库或状态库在明确需求、影响和维护责任后另行评估。模块样式默认 scoped；主题变量与全局基础样式由公共层维护。

## 分工与实施批次

按 D 提案，M2 组拟议负责公共登录和首版 HTTP 认证接入，M1 负责本模块页面及对公共能力的接入，M3 负责其通知/审计能力。公共外壳、导航和样式实施任务须指定集成人，由受影响模块评审；本次文档整理不代表已指定个人或获得各组批准。

1. 公共框架与基础样式：导航、布局、手机菜单、公共反馈及错误页面；验证三个模块入口。
2. M1 页面原型：搜索、座位查看、我的预约及正常/空/错误状态；演示数据明确标识。
3. 真实身份与查询：接入 D 身份/主数据和 M1 查询接口，验证身份恢复、深链接、过期、切换与数据隔离。
4. 预约完整流程：按独立业务任务接入预约、取消、签到、提醒和违约，补充相应测试。

每批实施前填写 [任务模板](../../../docs/ai-task-template.md)，确定允许目录、契约状态、验收与共享变更评审人。真实提供方不可用时，在消费方记录依赖缺口；使用运行时临时依赖须另按根规则明确授权与清理清单。本目录的独立展示原型不参与应用运行或部署，不是提供方替代服务。
